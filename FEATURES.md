## 🔹 Фича 1: Анализ запроса с оценкой Score

### Что делает
Анализирует пользовательский запрос перед отправкой к AI и выставляет оценку 0–100 по 4 критериям.

### Критерии оценки

| Критерий | Вес | Что проверяем |
|----------|-----|---------------|
| **Ясность** | 25% | Расплывчатые слова («сделай хорошо», «быстро»), отсутствие конкретики |
| **Полнота** | 35% | Указаны ли: входные данные, выходные, формат, обработка ошибок |
| **Контекст** | 25% | Зависимости, ограничения, окружение (браузер/Node.js/мобилка) |
| **Тестируемость** | 15% | Можно ли написать тесты (чистые функции, явные зависимости) |

### Алгоритм расчёта

```typescript
interface PromptAnalysis {
  clarity: number;      // 0–100
  completeness: number; // 0–100
  context: number;      // 0–100
  testability: number;  // 0–100
  score: number;        // Итог: взвешенное среднее
  issues: Issue[];      // Список проблем
  suggestions: string[];// Рекомендации
}

interface Issue {
  criterion: 'clarity' | 'completeness' | 'context' | 'testability';
  severity: 'low' | 'medium' | 'high';
  message: string;      // Что не так
  example?: string;     // Пример проблемы
  fix?: string;         // Как исправить
}
```

### Примеры проверок

#### Ясность (Clarity)
| Паттерн | Проблема | Рекомендация |
|---------|----------|--------------|
| `/(сделай|напиши|создай)\s+хорош/i` | Расплывчатое «хорошо» | «Укажите конкретные критерии: скорость, читаемость, покрытие тестами» |
| `/быстро|эффективно|оптимально/i` | Неясно, что имеется в виду | «Укажите метрики: <100ms, O(log n), без блокировок» |
| `/и\s+т\.д\.|и\s+так\s+далее|etc/i` | Неполное описание | «Перечислите все требования явно» |

#### Полнота (Completeness)
| Вопрос | Если «нет» → проблема |
|--------|----------------------|
| Указан ли тип входных данных? | «Неясно, что функция получает на вход» |
| Указан ли формат возврата? | «Неясно, что функция должна вернуть» |
| Описана ли обработка ошибок? | «Код может упасть без обработки» |
| Есть ли примеры использования? | «AI может неправильно понять контекст» |

#### Контекст (Context)
| Паттерн | Проблема |
|---------|----------|
| Нет упоминания окружения | Неясно: браузер, Node.js, мобильное приложение |
| Нет упоминания зависимостей | AI может использовать недоступные библиотеки |
| Нет ограничений | AI предложит решение, которое не впишется в архитектуру |

#### Тестируемость (Testability)
| Паттерн | Проблема |
|---------|----------|
| Глобальные переменные | Тесты будут зависеть от состояния |
| Скрытые побочные эффекты | Невозможно изолировать тест |
| Отсутствие явных зависимостей | Сложно замокать для теста |

## 🔹 Фича 2: Проверка кода с интерактивными предупреждениями

### Что делает
Анализирует код, сгенерированный AI, на 4 категории проблем и предоставляет интерактивный отчёт.

### Категории проверок

#### 🚫 Безопасность (Security)
| Проверка | Паттерн | Риск |
|----------|---------|------|
| `eval()` | `/\beval\s*\(/i` | Выполнение произвольного кода |
| `innerHTML` | `/\.innerHTML\s*=/i` | XSS уязвимость |
| Жестко закодированные секреты | `/(api[_-]?key|secret|password)\s*=\s*['"][^'"]+['"]/i` | Утечка учетных данных |
| `dangerouslySetInnerHTML` | React-специфично | XSS в React |
| Конкатенация SQL | `/["'].*\+.*\+.*["']/` | SQL-инъекция |

#### 🐌 Производительность (Performance)
| Проверка | Паттерн | Риск |
|----------|---------|------|
| N+1 запросы в цикле | `for.*fetch|forEach.*await` | Блокирующие запросы |
| Отсутствие кэширования | Мемоизация не найдена | Повторные вычисления |
| Синхронные операции | `readFileSync`, `fs.readFileSync` | Блокировка event loop |
| Большие циклы без оптимизации | `for.*length` без кэша | Лишние итерации |

#### 💣 Хрупкость (Fragility)
| Проверка | Паттерн | Риск |
|----------|---------|------|
| Нет обработки ошибок | Нет `try/catch`, `.catch()` | Падение при ошибке |
| Игнорирование null/undefined | `\.map\(|\.filter\(|\.find\(` без `?\. ` | TypeError |
| Отсутствие проверок границ | `array[index]` без проверки | undefined |
| Глобальные переменные | `window\.` без инкапсуляции | Конфликты имён |

#### 🧪 Тестируемость (Testability)
| Проверка | Паттерн | Риск |
|----------|---------|------|
| Побочные эффекты в чистых функциях | `console.log`, DOM внутри функции | Сложно тестировать |
| Отсутствие явных зависимостей | Импорт внутри функции | Сложно замокать |
| Жесткая связка с DOM/API | Прямые вызовы fetch без абстракции | Нужны моки |

### Структура данных

```typescript
interface CodeAnalysis {
  code: string;
  language: string;        // 'typescript' | 'javascript' | 'python' | ...
  issues: CodeIssue[];
  summary: {
    security: number;      // Количество проблем
    performance: number;
    fragility: number;
    testability: number;
  };
  riskLevel: 'low' | 'medium' | 'high' | 'critical';
}

interface CodeIssue {
  id: string;              // Уникальный ID (например, 'SEC-001')
  category: 'security' | 'performance' | 'fragility' | 'testability';
  severity: 'low' | 'medium' | 'high' | 'critical';
  line?: number;           // Номер строки (если определён)
  code: string;            // Проблематичный фрагмент
  message: string;         // Что не так
  why: string;             // Почему это проблема
  fix: string;             // Как исправить
  fixedCode?: string;      // Готовое исправление
}
```

1. **Клик на проблему** → подсветка в коде (если есть номер строки)

3. **Кнопка «Игнорировать»** → пометка «ложное срабатывание», скрытие
4. **Фильтры** → показать только Security / Performance / etc.
5. **Сортировка** → по важности / по категории / по строке

## 🔹 Фича 5: Режим новичка 🎓

### Что делает
Объясняет сложные термины и концепции прямо в интерфейсе. Помогает новичкам понимать, **почему** что-то является проблемой, а не просто **что** является проблемой.

### Когда активируется

| Триггер | Действие |
|---------|----------|
| Первый запуск | Предложить включить режим новичка |
| Клик по иконке ℹ️ рядом с термином | Показать объяснение |
| Неизвестный термин в предупреждении | Авто-подсветка с тултипом |
| Пользователь выделяет текст | Контекстное меню «Объяснить» |

### База терминов

```typescript
interface TermDefinition {
  term: string;              // Термин (например, "eval")
  category: 'security' | 'performance' | 'concept' | 'pattern';
  level: 'beginner' | 'intermediate' | 'advanced';
  short: string;             // 1 предложение
  full: string;              // Развёрнутое объяснение
  example: {
    bad: string;             // Плохой пример
    good: string;            // Хороший пример
    explanation: string;     // Почему это важно
  };
  relatedTerms: string[];    // Связанные термины
  externalLinks?: string[];  // Ссылки на документацию
}
```

## 🔹 Фича 6: Быстрые шаблоны запросов ⚡

### Что делает
Предлагает готовые шаблоны запросов для типичных задач. Пользователь выбирает шаблон → заполняет поля → получает готовый качественный запрос.

### Категории шаблонов

| Категория | Примеры шаблонов |
|-----------|------------------|
| **Функции** | «Напиши функцию для...», «Создай утилиту...» |
| **Компоненты** | «React-компонент для...», «Форма с валидацией...» |
| **API** | «GET-запрос к...», «REST API для...» |
| **Тесты** | «Напиши тест для...», «Покрыть тестами...» |
| **Рефакторинг** | «Улучши код...», «Оптимизируй функцию...» |
| **Объяснение** | «Объясни код...», «Что делает эта функция...» |

### Структура шаблона

```typescript
interface PromptTemplate {
  id: string;
  name: string;              // Название шаблона
  category: 'function' | 'component' | 'api' | 'test' | 'refactor' | 'explain';
  description: string;       // Краткое описание
  icon: string;              // Эмодзи или иконка
  
  // Поля для заполнения
  fields: TemplateField[];
  
  // Результат — готовый запрос
  generatePrompt: (values: Record<string, string>) => string;
  
  // Примеры использования
  examples: {
    title: string;
    filledFields: Record<string, string>;
    result: string;
  }[];
  
  // Мета-данные
  usageCount: number;        // Сколько раз использован
  avgScore: number;          // Средняя оценка Score
  tags: string[];
}

interface TemplateField {
  name: string;              // Имя поля (ключ)
  label: string;             // Отображаемое название
  type: 'text' | 'textarea' | 'select' | 'checkbox';
  placeholder?: string;      // Подсказка в поле
  required: boolean;
  help?: string;             // Подсказка рядом с полем
  options?: string[];        // Для type='select'
  defaultValue?: string;
}
```

```typescript
export function usePromptHistory(userId: string | undefined) {

        .eq('user_id', userId)
        .order('created_at', { ascending: false })
        .limit(100);

      if (error) throw error;
      return data;
    },

  });

    mutationFn: async (prompt: {

      score: number;
```

### ReCaptcha v3 интеграция

```typescript
// src/lib/recaptcha.ts
export const loadReCaptcha = (): Promise<void> => {
  return new Promise((resolve, reject) => {
    if ((window as any).grecaptcha) {
      resolve();
      return;
    }

    const script = document.createElement('script');
    script.src = `https://www.google.com/recaptcha/api.js?render=${import.meta.env.VITE_RECAPTCHA_SITE_KEY}`;
    script.async = true;
    script.defer = true;
    script.onload = () => resolve();
    script.onerror = () => reject(new Error('Failed to load ReCaptcha'));
    document.head.appendChild(script);
  });
};

export const executeReCaptcha = async (action: string): Promise<string> => {
  if (!(window as any).grecaptcha) {
    throw new Error('ReCaptcha not loaded');
  }

  return (window as any).grecaptcha.execute(import.meta.env.VITE_RECAPTCHA_SITE_KEY, {
    action
  });
};
```

```typescript
// supabase/functions/validate-captcha/index.ts
import { serve } from 'https://deno.land/std@0.168.0/http/server.ts';

const RECAPTCHA_SECRET_KEY = Deno.env.get('RECAPTCHA_SECRET_KEY')!;

serve(async (req) => {
  const { token, action } = await req.json();

  const response = await fetch(
    `https://www.google.com/recaptcha/api/siteverify`,
    {
      method: 'POST',
      headers: {
        'Content-Type': 'application/x-www-form-urlencoded',
      },
      body: `secret=${RECAPTCHA_SECRET_KEY}&response=${token}`,
    }
  );

  const result = await response.json();

  if (!result.success || result.score < 0.5 || result.action !== action) {
    return new Response(
      JSON.stringify({ valid: false, reason: 'Invalid captcha' }),
      {
        status: 400,
        headers: { 'Content-Type': 'application/json' },
      }
    );
  }

  return new Response(
    JSON.stringify({ valid: true }),
    {
      headers: { 'Content-Type': 'application/json' },
    }
  );
});
```

### Синхронизация: локально ↔ облако

```typescript
// src/hooks/useSync.ts
import { useEffect } from 'react';
import { supabase } from '@/lib/supabase';
import { localStorage } from '@/utils/storage/localStorage';

export function useSync(userId: string | undefined) {
  useEffect(() => {
    if (!userId) return;

    // Загрузка данных из облака при входе
    const syncFromCloud = async () => {
      const { data } = await supabase
        .from('user_progress')
        .select('*')
        .eq('user_id', userId)
        .single();

      if (data) {
        localStorage.set('truthprompt:progress', data);
      }
    };

    syncFromCloud();

    // Подписка на изменения в реальном времени
    const channel = supabase
      .channel('user_changes')
      .on(
        'postgres_changes',
        {
          event: '*',
          schema: 'public',
          table: 'user_progress',
          filter: `user_id=eq.${userId}`
        },
        (payload) => {
          // Обновляем локальное хранилище
          localStorage.set('truthprompt:progress', payload.new);
        }
      )
      .subscribe();

    return () => {
      supabase.removeChannel(channel);
    };
  }, [userId]);
}
```

#### 2. Интеграция на фронтенде

```typescript
// src/hooks/useReCaptcha.ts
import { useEffect, useState } from 'react';

declare global {
  interface Window {
    grecaptcha: {
      execute(siteKey: string, options: { action: string }): Promise<string>;
    };
  }
}

export function useReCaptcha(action: string) {
  const [token, setToken] = useState<string | null>(null);

  useEffect(() => {
    const script = document.createElement('script');
    script.src = `https://www.google.com/recaptcha/api.js?render=${import.meta.env.VITE_RECAPTCHA_SITE_KEY}`;
    script.async = true;
    document.head.appendChild(script);

    return () => {
      document.head.removeChild(script);
    };
  }, []);

  const execute = async () => {
    const newToken = await window.grecaptcha.execute(
      import.meta.env.VITE_RECAPTCHA_SITE_KEY,
      { action }
    );
    setToken(newToken);
    return newToken;
  };

  return { token, execute };
}
```

#### 4. Валидация на бэкенде (Supabase Edge Function)

```typescript
// supabase/functions/auth/signup/index.ts
import { serve } from 'https://deno.land/std@0.168.0/http/server.ts';

const RECAPTCHA_SECRET_KEY = Deno.env.get('RECAPTCHA_SECRET_KEY');

async function verifyRecaptcha(token: string): Promise<boolean> {
  const response = await fetch(
    'https://www.google.com/recaptcha/api/siteverify',
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: `secret=${RECAPTCHA_SECRET_KEY}&response=${token}`,
    }
  );
  
  const data = await response.json();
  return data.success && data.score > 0.5; // score > 0.5 = человек
}

serve(async (req) => {
  const { email, password, recaptchaToken } = await req.json();
  
  // Проверяем reCAPTCHA
  const isHuman = await verifyRecaptcha(recaptchaToken);
  if (!isHuman) {
    return new Response(
      JSON.stringify({ error: 'Bot detected' }),
      { status: 403, headers: { 'Content-Type': 'application/json' } }
    );
  }
  
  // ... продолжаем регистрацию
});
```

## 🔧 GitHub Actions CI/CD

### Структура workflow

```yaml
# .github/workflows/ci.yml
name: CI/CD

on:
  push:
    branches: [main, dev]
  pull_request:
    branches: [main]

jobs:
  lint-and-build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: web/package-lock.json

      - name: Install dependencies
        run: npm ci
        working-directory: ./web

      - name: Run ESLint
        run: npm run lint
        working-directory: ./web

      - name: Type check (TypeScript)
        run: npx tsc --noEmit
        working-directory: ./web

      - name: Build
        run: npm run build
        working-directory: ./web
        env:
          VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_URL }}
          VITE_SUPABASE_ANON_KEY: ${{ secrets.VITE_SUPABASE_ANON_KEY }}

      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: dist
          path: web/dist
          retention-days: 7

  # Опционально: тесты
  test:
    runs-on: ubuntu-latest
    needs: lint-and-build

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: web/package-lock.json

      - name: Install dependencies
        run: npm ci
        working-directory: ./web

      - name: Run tests
        run: npm test
        working-directory: ./web
        env:
          CI: true
```

### Настройка secrets в GitHub

1. Перейти в репозиторий на GitHub
2. **Settings** → **Secrets and variables** → **Actions**
3. Добавить secrets:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - `VITE_RECAPTCHA_SITE_KEY`

### Автодеплой на Vercel

Vercel автоматически деплоит при пуше в main/dev ветку. Для ручного триггера:

```yaml
# .github/workflows/deploy.yml
name: Deploy to Vercel

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: web/package-lock.json

      - name: Install dependencies
        run: npm ci
        working-directory: ./web

      - name: Install Vercel CLI
        run: npm install -g vercel

      - name: Pull Vercel environment
        run: vercel pull --yes --environment=production --token=${{ secrets.VERCEL_TOKEN }}
        working-directory: ./web

      - name: Build project
        run: vercel build --prod --token=${{ secrets.VERCEL_TOKEN }}
        working-directory: ./web

      - name: Deploy to Vercel
        run: vercel deploy --prebuilt --prod --token=${{ secrets.VERCEL_TOKEN }}
        working-directory: ./web
```

**Получение Vercel Token:**
1. Перейти в [Vercel Account Settings](https://vercel.com/account/tokens)
2. Создать новый токен
3. Добавить в GitHub Secrets как `VERCEL_TOKEN`
